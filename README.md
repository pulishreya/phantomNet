# PhantomNet: Generative Cyber-Deception (LLM Honeypots)

PhantomNet is a **honeypot whose shell is generated by a Large Language Model**. Traditional honeypots
(Cowrie, Kippo) replay canned responses, so a skilled attacker can fingerprint them in a few commands.
PhantomNet combines a **stateful deterministic core** with an **LLM "long tail"** that improvises realistic
output for commands it has never seen. Every move is logged, tagged with **MITRE ATT&CK** techniques and shown
on a live dashboard.

> Internship project - defensive security / threat intelligence.

## Key features
| Feature | What it does |
|---|---|
| Hybrid deception engine | Stateful fake filesystem (`cd`, `ls`, `cat`, `mkdir`, `echo > file`, `rm`) plus LLM/mock output for everything else |
| Pluggable LLM backends | `mock` (offline, default), `anthropic` (Claude API), `ollama` (local). Falls back to mock if the model is unreachable |
| Session consistency | Per-session filesystem and transcript are fed to the LLM, so created files and paths persist |
| Honeytokens | Decoy files (`config.php.bak`, `/etc/shadow`, SSH keys) raise `honeytoken_access` events |
| Prompt-injection defence | "Ignore previous instructions..." style input is detected, logged and never reaches the LLM |
| Safe by design | Nothing is executed; `wget`/`curl` always appear to fail; LLM is told to treat commands as data |
| ATT&CK mapping | 18 rules map commands to techniques (T1105, T1003.008, T1082, T1070.003 ...) |
| Telemetry | JSONL log + SQLite + web dashboard + `/api/stats` JSON |

## Architecture
```
 Attacker --TCP (telnet/netcat style)--> honeypot.py (asyncio server, fake login)
                                              |
                                              v
                                         engine.py -- injection filter --> log + decoy reply
                                              |
                      +-----------------------+------------------------+
                      v                                                v
        deterministic builtins (FakeFS)                llm.py (mock | anthropic | ollama)
        cd ls cat mkdir touch rm echo id ...           context = session history + known files
                      \                                                /
                       +-------------> output to attacker <-----------+
                                              |
                              logger.py (JSONL + SQLite) + mitre.py tags
                                              |
                                        dashboard.py
```

## Quick start (standard library only, Python 3.9+)
```bash
git clone https://github.com/<your-username>/PhantomNet.git && cd PhantomNet
python -m phantomnet run --port 2222          # start the honeypot
nc localhost 2222                              # another terminal: act as the attacker
python scripts/attacker_sim.py 2222            # or run the scripted demo attacker
python -m phantomnet dashboard --port 8080     # http://localhost:8080
python -m phantomnet report                    # JSON summary
python -m unittest discover -s tests -v        # tests
```
Log in with any username/password. The 2nd attempt succeeds, so the first failure looks realistic.

### Use a real LLM
```bash
export ANTHROPIC_API_KEY=your-key
python -m phantomnet run --backend anthropic   # model via PN_MODEL (default claude-sonnet-5-5)

ollama pull llama3
python -m phantomnet run --backend ollama      # fully local
```
Env vars: `PN_PORT`, `PN_BACKEND`, `PN_MODEL`, `PN_OLLAMA_URL`, `PN_OLLAMA_MODEL`, `PN_LOG_DIR`, `PN_HOSTNAME`.

### Docker
```bash
docker build -t phantomnet . && docker run -p 2222:2222 -v $PWD/logs:/data phantomnet
```

## Layout
```
phantomnet/   honeypot (server), engine (commands), session (state/FakeFS), llm (backends),
              mitre (ATT&CK), logger, dashboard, config, __main__ (CLI)
scripts/      attacker_sim.py
tests/        unit tests
docs/         PROJECT_REPORT.md
```

## Responsible deployment
Run only on infrastructure you own, inside an isolated network/VM/container with no route to production.
Captured credentials are attacker-supplied data, so treat logs as sensitive. For defence and research only.

## Limitations & future work
Telnet-style transport instead of full SSH (swap in `asyncssh`); pipes and most redirections are delegated to the
backend; LLM latency can be a tell (add caching); add HTTP/FTP/MySQL decoys, ELK/Grafana export and IOC extraction.
